Agentic Stack Map Presentation Resources

Quick reference

Four layers, two focus harnesses, three context options.

Use this as the handout: OMP and Hermes are the focus harnesses; Matt Pocock, caveman, and Karpathy rules are the behavior layer; LeanCTX is the used context MCP; RTK and Headroom are alternatives; Codebase Memory and AgentMemory handle long-lived context.

The layer map

1. Harness

Job: run the agent session, permissions, UI, tool execution, and session state.

Focus: OMP / Oh My Pi and Hermes.

Alternatives: OpenCode, Codex CLI, Claude Code, Cursor, and other MCP-compatible clients.

2. Skill

Job: change the agent’s behavior with reusable instructions and support files.

Focus: Matt Pocock `ask-matt`/`tdd`, caveman compression, Karpathy-style coding rules.

Alternatives: project-local skills, team-specific runbooks, workflow-specific skills.

3. MCP server

Job: expose tools, resources, and prompts to the harness through a standard protocol.

Used: LeanCTX / `lean-ctx` for compressed local context access.

Alternatives: RTK for command-output token reduction; Headroom for general MCP compression/retrieval.

4. Memory

Job: keep useful context available after the immediate chat.

Structural: `codebase-memory-mcp` stores a rebuildable graph of code relationships.

Narrative: `agentmemory` stores session history, rationale, preferences, and discoveries.

Matt Pocock implementation order

1 · Shape

wayfinder / grill-with-docs

Use `wayfinder` for foggy multi-session work. Use `grill-with-docs` when the codebase and project docs can sharpen the idea now.

2 · Specify

to-spec

Convert the shaped idea into a concrete spec with behavior, constraints, boundaries, and acceptance criteria.

3 · Split

to-tickets

Break the spec into tracer-bullet tickets with dependencies and clear verification per ticket.

4 · Build

implement

Execute one ticket at a time. Pull in TDD internally when behavior can be locked with red → green tests.

5 · Review

code review

Review against standards and spec before declaring the change complete.

Detailed presenter notes by layer

Harness detail

Explain: the harness is the runtime and permission boundary. OMP is the terminal-first local development loop. Hermes is the agent surface with first-class skills, MCP management, sessions, and memory configuration.

Do not imply: harnesses automatically solve context quality or memory. They expose and coordinate the pieces that do.

Skill detail

Explain: Matt Pocock skills define the implementation order: `wayfinder`/`grill-with-docs` to shape, `to-spec` to specify, `to-tickets` to split, `implement` to build, and `code-review` to check.

Do not imply: `implement` is the first step. It belongs after the problem is shaped, specified, and ticketed.

Context MCP detail

Explain: context MCPs reduce waste before content reaches the model. LeanCTX is the used local context runtime. RTK targets noisy command output. Headroom targets broad content compression/retrieval.

Do not imply: all token savers have the same scope. File exploration, shell output, and general tool-output compression are different problems.

Memory detail

Explain: Codebase Memory MCP is structural: symbols, calls, routes, architecture, impact. AgentMemory is narrative: preferences, rationale, session history, decisions-in-progress.

Do not imply: generated memory is canonical truth. Accepted decisions and domain language should still be promoted to durable plain text.

Long-term memory detail

Structural
codebase-memory-mcp

Input

Repository files, symbols, calls, imports, routes, tests, and file relationships.

Store

Rebuildable local code graph with nodes and edges for structural code questions.

Query

Callers, callees, architecture, impact, routes, hotspots, dead-code candidates.

Boundary

Great for structure; wrong place for rationale or accepted decisions.

Narrative
agentmemory

Input

Conversation history, user preferences, decisions, discoveries, debugging history.

Store

Persistent narrative recall across sessions, harness restarts, and compaction boundaries.

Query

“Why did we choose this?”, “what did the user prefer?”, “what happened last time?”

Boundary

Great for continuity; accepted decisions still belong in plain text docs/ADRs.

Speaker’s 60-second summary

“The stack has four layers. OMP and Hermes are harnesses: they run the agent session. Skills are behavior: the Matt Pocock implementation path is wayfinder/grill-with-docs → to-spec → to-tickets → implement → code review; caveman compresses communication; Karpathy rules keep edits simple and verifiable. MCP servers are capability plugs. LeanCTX is the context layer used here; RTK and Headroom are alternatives for token reduction and compression. Long-lived handling splits again: Codebase Memory MCP gives a structural code graph, while AgentMemory keeps narrative session memory.”
